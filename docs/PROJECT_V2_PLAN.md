## 1. 目标、范围与版本关系

2.0 要回答三个可被否定的问题：卫星退化主要发生在哪个环节；修正后能否超过最强无卫星方案；
收益能否在新时间、新站点和有延迟/缺帧的条件下保持。目标是得到可信结论，不预设卫星一定胜出。

执行顺序为：已有产物诊断 → 正确性与算力验收 → 足量训练与强基线 → 少量有依据的卫星改进 →
有条件的数据扩展与独立确认 → 交付。用户已选择路线 B；按 ADR-009 先完成正确性、设备与数据门槛，再执行新开发折对照，不要求跑满路线 A。
即使路线 B 不执行，路线 A 的负结果、强纯功率模型和离线演示仍是有效交付。

## 2. 已知事实与证据边界

结果来自 [精简验收报告](COMPACT_DEVELOPMENT_REPORT.md) 和
[机器可读对照](audits/compact-comparison-2026-09-28.json)。误差单位为装机容量百分点，越小越好。

| 方案 | 开发日间主 MAE | 留出站点日间主 MAE | 参数量 |
|---|---:|---:|---:|
| PowerMLP | 4.375 | 7.461 | 6,342 |
| Smart Persistence | 4.954 | 6.983 | 0 |
| 配对纯功率 `power_solar` | 5.103 | 8.315 | 5,478 |
| 卫星融合 `full` | 5.397 | 9.119 | 21,446 |
| Persistence | 5.560 | 8.341 | 0 |

- full 相对 MLP 退化约 23.35%，相对配对 power_solar 退化约 5.75%。前者混合了架构和输入信息差异；
  后者更接近卫星增量对照，但仍不完全控制参数量与优化轨迹。
- 九组近期训练均为 CPU、最多 8 epochs。MLP 最佳轮次 8/7/7，power_solar 为 8/8/5，full 为 3/5/8。
  达到上限不证明未收敛；提前出现最好值也不单独证明过拟合。早期 GPU 结果属于旧协议，不能混排。
- 现有卫星结构是逐帧 CNN → 全局平均池化 → GRU，已经处理四帧时间序列。
  待检验的是空间信息在时间建模前被压缩、运动表达是否足够，而不是“完全没有时序”。见
  [fusion.py](../src/cloud2watt/models/fusion.py)。
- 输入 128×128 经平均池化变为 32×32；CNN 内还有三次 stride=2 下采样。
  “细节可能损失”是结构依据，不是已证实的主要失败原因。
- 卫星训练在 [experiment.py](../src/cloud2watt/experiment.py) 使用 `jitter_padding=4`，
  [加载器](../src/cloud2watt/data/satellite_loader.py) 按 seed 与样本索引固定平移，各轮不变。
  增强幅度与站点相对位置是否匹配尚待检验，应先于大型网络升级检查。
- 正常/置零/错配误差分别为 5.397/5.577/5.424。当前置零同时将帧 mask 清零，表示整条卫星分支缺失；
  当前 shuffle 是 batch 内循环移位，并非保证云场无关的随机配对。二者仅为输入敏感性证据。
- `train_masked_mae` 是训练模式下全部六时效有效目标损失，`validation_daylight_primary_mae`
  是日间三个时效指标。不能直接把两列相减当作泛化差距；需补同口径、`eval()` 模式的训练诊断集评分。
- sweep=y 修正和 60 次源裁剪比对已完成，但这不等于绝对地理定位、云视差、扫描时刻、到达时间均已验证。
- 原 30 天的历史 test 已曝光。四个留出站点也已用于开发诊断；都不能成为新的独立最终测试。

## 3. 原因—解决—验证矩阵

优先级 P0 表示错误会使比较失效；P1 表示优先开展的低成本诊断；P2 表示有证据再升级。
下表是可证伪假设，不是已确认故障清单。每一项都要输出“支持／不支持／证据不足”及适用范围。

| ID / 优先级 | 假设与诊断 | 对应改进 | 验证与否定条件 |
|---|---|---|---|
| H01 / P0 | 标签、单位、容量、QC 或时间支持不一致；检查 UTC、窗口边界、站点容量、完整 bin 与坏数据 | 保持采样代理契约；修正确定性错误；真正积分目标另立数据与标签版本 | 源→标签抽样重建、人工算例、边界测试和同键 hash 全部一致；半小时交叉核对仅用于尺度诊断，不能证明十五分钟积分语义 |
| H02 / P0 | 地理中心、轴方向、帧时间或发布延迟错位 | 在 source metadata 约束下修正投影/时间；显式加入 available_time、frame_age、位置不确定性 | 海岸线/地标叠图、20 站点多个日期的源像素比对；历史平移只作诊断，不按验证误差寻找“正确位置”；禁止未来帧。修正后同协议重训 |
| H03 / P0 | 标准化、通道顺序、缺帧、mask、缓存身份或归一化尺度存在实现问题 | 每折训练区间拟合统计，冻结通道单位、有效帧采样、缺帧路径和缓存 hash | 有效像素/标签有限；训练统计不读验证/测试；部分与全缺帧、损坏缓存、梯度、恢复用合成测试与小样本验证 |
| H15 / P1 | 固定空间 jitter 使云与站点相对位置改变；随机性只随样本变而不随 epoch 变 | 将增强显式配置并纳入 hash，先比较 jitter=0 与现有 4；后续小幅增强同步更新位置通道 | 配对训练仅改变 jitter；查原像素地面距离和偏移图；若禁用后不改善，不把增强认定为原因。新增位置通道另算候选 |
| H04 / P1 | 八轮训练不足、学习率不合适或某分支学不动 | 三类模型统一更长上限；记录梯度/更新范数、学习率与同口径曲线；只对诊断指出的问题调优化器 | 先用相同 CPU FP32 条件隔离预算变化；若足量训练仍无改善，降低“只是没训够”的优先级。具体预算见 E10 |
| H05 / P1 | 有效天气样本少且相关性强；更多参数过拟合 | 正则化、缩小卫星分支、训练日期分层采样；有条件增加季节/区域 | 同口径 train-eval/validation 曲线、日期块学习曲线、站点宏平均；不能把相邻窗口或三种子当作独立天气样本 |
| H06 / P1 | 下采样、全局池化损失站点附近的云边界与位置 | 固定视野比较 32²/64²/128²；位置网格池化或局部+外围双尺度；加入站点相对坐标 | 分辨率和视野一次只改一个；报告物理覆盖、参数和耗时；若性能不变且统计不确定，不能声称高分辨率必需 |
| H07 / P1 | GRU 获得的帧向量不足以表示云位移 | 最新单帧重复对照；帧差/光流+MLP；保留空间特征的轻量 3D CNN 或 ConvGRU，先选一种 | 固定最后一帧、历史顺序/历史移除敏感性；帧差与运动模型需独立重训；历史扰动是分布外诊断，不单独构成因果证明 |
| H08 / P1 | 卫星分支干扰已有有效的功率表示，或优势只是容量差异 | 冻结强功率主干，学习有界残差；按时效门控；与容量接近的无卫星网络及同主干消融比较 | 必须同时超过 B* 与架构配对 P*；检查残差幅度、门控是否饱和、缺帧是否精确退回基线；不能只赢弱 power_solar |
| H09 / P1 | 训练目标与日间主指标不对齐，夜间/非主要时效主导优化 | 提高日间三时效损失权重，同时保留六输出的非零监督；相同权重也用于无卫星对照 | 逐时效有效数量与梯度贡献审计；同时报告其他时效和夜间退化；主评分不随损失试验改变 |
| H10 / P1 | 卫星价值集中在部分天气/时效，被汇总掩盖 | 分时效、站点、季节、历史波动、太阳高度和晴空指数诊断；有依据再做输入可知的条件门控 | 所有预登记组并列显示支持数和误差；未来波动/爬坡分组标为事后分析，不可用来实时挑模型或替换失败的主比较 |
| H11 / P2 | VIS/IR 单位、太阳角度、通道信息量、云视差或物理表征不足 | 单通道族消融；训练期归一化；晴空/云指数；有依据才引入云高视差修正或更多通道 | 通道独立重训与置零诊断分开；极低太阳高度不做不稳定除法；新物理产品须核实同一时刻可用性与来源 |
| H12 / P2 | 跨站点/季节域偏移、方位倾角误差、设备故障/限发与云无关 | 稳健静态特征、缺失标志、只用过去数据的校准；按地域分组；确认后扩时空覆盖 | 坐标/容量覆盖、站点宏平均、已知与未见站点独立报告；禁止用留出站点未来标签做校准；异常处理规则不能按模型误差制定 |
| H13 / P1 | 实际卫星晚到、连续缺帧或功率缺失抵消档案实验收益 | 0/15/30 分钟延迟回放、帧龄与缺失特征、模态 dropout、明确回退策略 | 共同样本精度与全量服务表现分开；所有模型同一 issue clock；缺失故障、回退率、覆盖率与耗时一并验收 |
| H14 / P0 | 小验证集、多次试验、挑 seed/样例或不同评分集合造成偶然排名 | 固定样本/指标、试验登记、预算上限、日期块区间和新盲测 | 报告所有配置与失败；选择后开发 CI 仅作筛选证据；独立冻结测试才能支持最终结论 |

## 4. 路线 A：不扩数据，先找到可行动的证据

### A0. 只读复盘与可视证据

读取九组运行的 history、config、environment、metrics、validation predictions 和源码快照，
不解锁旧 test。输出三种子曲线、逐时效误差、日期/站点热图、误差与历史功率波动/帧龄关系。
历史完整每轮权重若不存在，不能补造逐轮 train-eval 曲线；现有 best/latest 只补它们对应的诊断，
从新运行开始逐轮记录同口径曲线。

案例按可复现规则选取：主指标退化最多/改善最多的前若干日期，加固定种子随机案例；三类均展示，
不只挑漂亮曲线。窗口按目标时间对齐，所有预测保留 issue 时间，避免重复预测被画成独立观测。
选择规则只使用开发分区，不读取新最终测试。

### A1. 正确性、地理和优化验收

先排除 H01–H03，再测优化与 GPU。有效帧不可 NaN；断帧不能跨空洞伪造连续历史；功率可用时刻
也须满足 issue 时刻约束。所有标准化只在本折训练站点/日期拟合，增强同步作用于帧、坐标和站点位置。
一般图像分类中的随机翻转/旋转不能直接套用，否则可能破坏地理方向与云移动语义。

现有卫星统计最多使用 512 个训练 `(site_index, frame_index)` 键；不同站点可能共享像素，
不能把键数当成独立影像数。检查按唯一时间/tile 分层后通道均值/尺度是否稳定；增大统计样本数
或改变取样方法需要新 statistics hash 和重新训练。延迟 ledger 已有实现，但普通加载器仍要求原四槽，
接入带延迟的新槽与帧龄是待实现任务，不能直接把已有函数称为完成延迟精度回测。

在固定小训练子集关闭 dropout/权重衰减，验证预测依赖各输入、卫星梯度非零、损失能明显下降；
用合成可学习目标验证可达到预设误差。真实小子集不能拟合时先定位优化/数据问题，不直接堆模型。
修复若改变输入或评分身份，建立新运行；不能把旧 best.pt 原地续成新协议结果。

### A2. 足量训练、强基线与损失对齐

先跑 E10：同样本三模型三种子、40 轮上限，保留原损失、分辨率及优化器差异并明确记录；
只检验“增大训练预算”是否改变结论。随后有限筛选 MLP、配对功率和至多一种树模型（或替代的 TCN），
Persistence 与 Smart Persistence 始终保留。相同完整数据与 checkpoint 规则不等于相同计算成本，
同时报告参数、优化步、样本暴露次数、训练和推理时间。

损失对齐作为独立实验：默认 `L = 0.8 × 日间三时效等权MAE + 0.2 × 原六时效全部有效目标MAE`，
让 15/180/240 分钟输出也有监督，避免产生未训练输出头。每个主要时效日间 MAE 先独立归约再等权平均；若一个微批缺某时效，
按预先实现的有效计数归约，不用零填充伪造贡献。更改损失必须同时给无卫星模型相应训练机会。
早停、排名的主指标不变，避免把训练策略和评价目标同时改变。

### A3. 诊断驱动的卫星候选

最多选择六个单因素候选，先做禁用空间 jitter 的低成本对照，再依据证据选择更高空间分辨率、
空间位置保留或强功率残差融合；改变神经网络结构的候选最多两个。
是否执行由 A0–A2 的证据决定，不同时铺开所有结构、通道、损失和分辨率组合。

推荐残差结构为 `预测 = Q(过去功率、太阳与静态特征) + g(可用输入、时效) × 卫星残差`。
Q 是 E30 冻结的强功率主干，其架构与训练规则固定；B* 是独立选出的竞争基线，两者不要求始终相同。
进入新折必须只在该折 fit 重训 Q，不能复用覆盖未来折数据的 E20 权重；若后续 B* 变更，不自动更换 Q。
首先冻结功率主干，残差输出零初始化，门控使用非零初始化以免两支同时无梯度；
之后若试联合微调，记为另一候选。门控只能使用 issue 时刻可知输入，不能用未来实际误差或云量。
门控归零/无卫星时必须精确退回 Q；只有 Q=B* 才称回退 B*。这不保证正常输入下总能优于竞争基线，仍需实验验证。

容量对照需单独训练无卫星网络，参数数尽量接近（目标差异不超过 10%，达不到时披露）。
新增宽度不能单独解释信息价值；若依靠更长功率历史，则强基线和配对对照都获得该历史。
引入多个时效模型或按天气切换，整体视作一个新策略并计入预算。

### A4. 更可靠的消融

所有扰动只读取开发资料。区分训练消融、输入敏感性、可用性压力三类，不能相互替代。

- **独立训练消融**：无卫星 P*、容量接近的无卫星模型、完整 F*；必要时静态单帧与时序模型。
- **时间信息**：四帧、重复最新有效帧、去除较早历史、历史顺序扰动；缺帧 mask 与帧龄一致变化。
- **更强错配**：同站点、相近太阳高度、相同有效帧模式但不同且不相邻日期的完整历史块；固定配对种子，
  排除相同/重叠历史窗口，记录云场相关性。若日期不足以构造低相关对照，标记不可判断。
  此操作仍可能引入分布偏移，不能称严格因果识别；不得从新最终测试抽取替换图像。
- **缺失敏感性**：保留原“分支缺失”置零语义；另测 mask 保持有效但像素为训练均值的输入，清楚区分二者。
- **通道与位置**：VIS/IR 分别训练消融；小范围站点位置扰动只量化鲁棒性，不用验证标签反向修正站点坐标。

## 5. 路线 B：有条件扩展数据并独立确认

启动条件是数据/QC/训练正确性门通过、已有诊断报告且成本可承受。路线 A 未胜出不强制取消路线 B：
若仍有明确的数据多样性假设，可预登记一次有界数据学习曲线；没有证据时停止卫星扩展。

建议先核查覆盖至少三个季节的连续资料，再视成本扩到全年。每季优先选不少于四周的连续开发窗口，
避免只挑晴天或表现好的月份；站点按地理组和可访问性选择。以上是设计目标，不是已发现可用数据。
先用元数据冻结来源 revision、绝对日期、站点名单、地理分组、下载字节上限和缓存上限，再下载/构建。
只在物理定位和统计语义一致时复用共享 tile；按区域重叠估算成本，不按站点数线性套用旧压缩比例。

开发采用三个验证窗口不重叠的 expanding-window 折。每折分 fit、inner-selection、outer-development：
训练统计与优化只用 fit，早停/选 checkpoint 用 inner，outer 用于跨折比较；所有边界按完整窗口及
至少 4 小时 embargo 隔离。若扩大预测时效，embargo 随最大目标支持范围增长。
每折允许使用此前开发标签扩展训练，但不允许未来折信息回流到早期折。

旧 30 天仅做开发/回归；任何新终测日期不得与已用于训练、调参、可视化或模型选择的时间角色重叠。
独立最终测试至少预留晚于全部开发窗口的连续 4–8 周，并预留完全未参与训练/选择的地理组；
地理组的全部历史标签排除在训练、标准化、校准和预训练之外。按坐标分组，不能随机分邻近站点冒充区域迁移。

独立测试分开回答“已知区域未来时间”和“未见区域未来时间”。站点/区域数量少时，
日期块区间只描述这些站点上的时间变化，不代表全国站点总体不确定性。相邻区域共享云场的限制须披露；
自监督预训练也不得接触最终时间影像或最终地理组对应的保留输入窗口。

最终评估接口尚需实现：使用隔离 manifest/文件或列读取过滤，先截断到授权分区再取标签，
不能仅依靠 `test_unlocked=false` 元数据声称标签从未被读取。仅在数据完整性、模型、基线、种子、
checkpoint、后处理和脚本 hash 冻结后一次性评分。若结果已查看后改变策略，原结果保留，下一次确认需新盲测。

## 6. 统一评价与继续/停止规则

令 `M` 为目标时刻太阳高度角严格大于 5° 的 30/60/120 分钟 MAE 等权平均。
容量归一化值 0.01 即装机容量 1 个百分点。六时效 MAE/RMSE/bias、全天和日间、站点宏平均、
日期支持数、缺失与失败率始终并列。所有候选同键、标签、mask；有效目标上 NaN/Inf 导致失败，不能删掉难样本。

`B*` 为登记候选中的最强无卫星策略，`P*` 为与 F* 匹配的无卫星结构，`F*` 为冻结的卫星策略。
`G = 1 - M(F*) / M(B*)`；基线 M≤1e-8 或非有限时不报百分比，只报绝对差并标记该门不可判断。
三种子误差先平均，再按折等权平均；不默认集成，不选表现最好的 seed。

| 层级 | 验收条件 | 允许的结论 |
|---|---|---|
| 工程完成 | 身份、正确性、恢复、有限值与产物通过 | 能运行、可追溯 |
| 路线 A 候选 | 旧开发分区平均 G≥5%，至少 2/3 种子改善，且比 P* 更好 | 值得进入新数据确认；不称独立胜出 |
| 路线 B 开发门 | 三折平均 G≥5%；至少 2/3 折和 2/3 种子方向改善；对 P* 平均亦改善 | 在所覆盖开发窗口内有潜力 |
| 开发稳健性 | 上述条件加配对日期块 95% CI 的 F*−B* 上界<0；3 日块敏感性不反向 | 为最终验证提供支持；不能忽略候选筛选偏差 |
| 最终时间/区域门 | 各分区独立满足 G≥5%、配对 CI 上界<0、至少 2/3 种子改善、对 P* 亦改善 | 只在通过的时间/区域范围内声明独立收益 |
| 退化或证据不足 | G≤0；或 0<G<5%；或 CI 跨 0/方向不稳，分别记录 | 负结果／有限改善／证据不足，不补跑到显著为止 |

CI 使用固定种子 2026、至少 2,000 次配对 UTC 日期块 bootstrap：每次保留当天所有站点、时效和
三种子预测，分别重算时效误差再平均；不把种子当作三倍样本。按 **issue 的 UTC 日期** 分块，
保留同一发布样本的所有时效；按目标日期分组的误差图仅作附加诊断。三折在折内重采样后等权聚合。
补连续 3 日块敏感性，不跨缺口/折拼接；少于 20 个有效 issue 日期仅报告描述性区间，不作显著性验收。
20 日是项目的保守下限，不是统计充分性的保证。

唯一主要比较是 F* 对 B* 的主指标；对 P* 为结构归因支持，其他组为探索性。
最终时间和区域分别给结论；如要提出“任一测试分区获胜”的总体显著性声明，两个检验须预登记多重比较校正。
若要新增天气/时效的确认性结论，先登记假设与校正方法，不能事后把最好的子组改成主结果。

## 7. 爬坡、可用性与工程交付

爬坡仍用 30 分钟归一化变化 ±0.20 为主阈值，0.10/0.15/0.25 为敏感性；
上升/下降分别统计。事件合并、一对一匹配、±15 分钟容忍和提前量定义在开发阶段冻结。
报告 F1、误报/站日、漏报、真实提前量、事件数量与日期块区间；每方向/分区少于 100 个事件仅作描述。
100 个事件不保证统计充分；不把容忍匹配命中冒充提前预警，不把稀少事件上的提升替代功率主指标。

可用性回放含卫星延迟 0/15/30 分钟、随机缺帧 10%/30%、连续中断 30/60 分钟及功率缺失。
比例是预设压力情景，不是实测故障率。先做不重训的压力测试；若增加模态 dropout/延迟训练，计入新候选。
卫星不可用时退回同一功率基线；功率也不可用时只使用冻结的晴空/历史策略或明确拒绝输出。
这里的功率回退指模型登记的 Q；若 Q 与 B* 不同，完整服务评价仍与 B* 比较并披露差距。
共同样本精度和包含所有 issue 的服务评价分表；不得靠丢弃缺帧时刻改善精度。

GPU 用于提高实验效率，不作为精度提升方案。补齐 CUDA FP32、AMP、梯度累积、暂停恢复测试后再切换；
记录 GPU 型号、驱动、CUDA/cuDNN、依赖锁、精度、随机状态、源码快照与 dirty diff。
CPU/GPU 不要求逐位相等，按预登记数值容差和多种子方向验收。规范依据见
[PyTorch 可复现性说明](https://docs.pytorch.org/docs/2.14/notes/randomness.html)。

交付包含实验登记、机器可读预测和指标、模型卡、失败与负结果、可复现命令、环境与算力账单、离线回放。
本地推理适配器先对齐离线 batch 预测，再测 batch=1 的含预处理 P50/P95 延迟、峰值内存及吞吐；
15 分钟发布周期下要求无积压，具体业务 SLA 在目标设备实测后登记。无实测输入延迟不能宣称线上可用。
概率预测、NWP、大型 Transformer、无界自监督训练、HRV 新数据和生产部署列为后续研究，不进入默认矩阵。

| 阶段 | 依赖与交付 | 粗估主动工作量 | 退出条件 |
|---|---|---|---|
| P0 证据复盘 | 九组产物审计、同口径诊断设计、H01–H15 状态 | 1–2 人日 | 每项假设有证据或明确缺口；不泄漏测试 |

| P2 路线 A | E10–E40、强基线、最多六个卫星候选、有限确认 | 3–6 人日 | 形成继续/停止结论和完整负结果 |
| P3 路线 B 数据门 | 覆盖清单、成本、绝对切分、隔离测试 | 3–5 人日 | 数据与预算登记完成；否则保留路线 A 交付 |
