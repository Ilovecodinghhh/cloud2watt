- BASELINE_REPORT.md 已公开旧数据版本 test 结果。因此“后续模型未读 test”和“整个项目从未查看 test”必须区分。
- 静态阅读发现：CNN 文档指定用 30/60/120 分钟选 checkpoint，当前训练脚本却按全部有效目标的平均 validation loss 选择。

上述差异需逐项复现后决定修复范围，不预先认定现有所有实验无效。

## 3. 提议冻结的全程规则

1. 区分工程运行成功、开发改善、跨窗口稳健改善和最终测试结论。
2. 模型比较共享相同的 site_id、issue_time、horizon、标签和目标 mask；评分前验证有效目标键的 hash。
3. 建议新主指标采用目标时刻太阳高度角大于 5° 的日间 30/60/120 分钟 MAE 等权平均，命名 daylight_primary_mae。这是待审核的协议变更，旧全天结果仍保留，但不混称同一指标。
4. 每个时效先单独评分，再对三个主要时效等权平均；任一主要时效没有有效样本时，该运行不能成为候选。
5. 并列报告全天、所有时效、低太阳高度角、RMSE、偏差、站点宏平均、有效目标数量和独立日期数。归一化功率的 MAE 已是容量归一化误差，不重复除以容量。
6. 最强基线、调参上限、种子、天气分组、事件阈值、统计方法在最终测试前冻结。
7. 新最终测试只允许预先定义的 schema、时间覆盖和 QC 核查；不做用于选择模型的预测图、目标分布探索或评分。
8. 空间验证一旦用于调参，就是开发验证；最终未见区域另外留出。不可把参与选择的验证站点继续当作完全独立证据。
9. 分别记录观测时间与实际可用时间。缺少真实发布延迟时，标注理想化可用性并做延迟情景回测，不宣称实时能力。
10. 所有 Markdown、代码和文本使用 UTF-8 无 BOM；真实数据、权重不进入 Git，沿用上游许可约束。

## 5. S1：指标、训练与恢复正确性

**目标：在长时间训练前解决会影响结论的问题。**

### S1.1 评估与选择

- 有效标签上的预测 NaN/Inf 触发失败，输出失败率和样本键；无效标签不计分。
- checkpoint、早停、候选排序和汇总统一使用 daylight_primary_mae。训练损失可保留六时效 masked MAE，但必须与选择指标分开命名。
- 统一结果 schema，保存逐时效指标、有效目标数、模型无关的 mask 与协议版本。
- 回归测试覆盖缺失目标、不等时效样本数、夜间、零基线误差和手算值。

### S1.2 训练与缺帧

- 验证全有效、首帧/中间/末帧缺失、全缺帧。不能直接把有效帧数量当作最后有效时刻的索引。
- 在拒绝缺帧、时序 mask 或带时间间隔编码中确定一种策略，训练/评估/推理一致。
- 比较梯度累积与等价大 batch 更新，覆盖末组不满和 microbatch 有效目标数不同的情况。
- 验证 AMP 的有限梯度与必要的缩放状态；GPU 数值检查仅在对应硬件可用时执行。
- 保存 RNG、优化器、早停和采样器恢复状态；明确以 epoch 边界恢复，中断的半个 epoch 允许重做。

### S1.3 运行身份与恢复

- 完成跳过条件至少覆盖配置、数据、切分、标准化、模型、seed、预算、指标协议和代码兼容版本。
- checkpoint、预测、指标、provenance 完整写出后才生成完成标记；采用临时文件和原子替换。
- 兼容的未完成运行显式恢复；不兼容运行创建新目录，不覆盖旧结果。
- 保存已验证环境依赖与硬件快照，不仅依据相同 run 名称判断身份。

### 交付与验收

- 修改现有 evaluation、fusion、training、experiment_matrix 及训练入口，不另建平行框架。
- 针对以上失败模式的回归测试、CPU 合成闭环、恢复测试和真实小样本验收通过。
- 中断恢复与连续训练在声明的确定性设置和容差内一致；无法保证 GPU 位级一致时明确限制。
- 旧实验分为可重新评分复用和必须重训。改变 checkpoint 选择、训练更新或输入语义时，不能只重命名旧结果。

**停止条件：协议未对齐、出现非有限值、恢复身份不可信时，不启动正式矩阵。**

## 6. S2：数据语义与扩容成本

**目标：在可信标签和实测资源成本上扩容。**

### 任务

- 核对 UK PV 固定 revision 的数据卡、schema 和字段说明，记录 5 分钟数据的能量/功率解释依据，以单位、物理范围和可比聚合样本交叉验证。
- 公开资料仍有歧义时准备询问材料供用户发送；不擅自联系外部人员，不用统计分布代替上游语义确认。
- 核查投影、像素地面尺度、裁剪中心和时间含义，抽查至少 5 个站点。
- 增加 observation_time / available_time 契约。真实延迟未知时比较理想、15 分钟、30 分钟延迟情景，明确这些不是实测 SLA。
- 实现按区域和时间共享卫星 tile，站点保存裁剪索引；处理边缘 halo、跨 tile 裁剪、通道顺序和缺帧。
- 用代表性短窗口对比旧布局与新布局的像素和样本，不先下载全年数据。
- 实测远程读取量、源缓存、派生数据、临时空间、进程 RSS、冷/热缓存吞吐和 P95 延迟。

### 交付与验收

- 数据语义 ADR、来源记录、共享 tile schema 和迁移说明。
- docs/DATA_SCALING_REPORT.md：按实际区域、重叠和压缩估算年度成本。
- 合成边界与真实裁剪一致；1,000 batch 不死锁；保留 RSS 曲线，预热后无持续上升趋势。
- 热缓存 batch size 8 目标至少 50 samples/s；未达标时分析是否仍能满足训练预算。
- 默认派生数据目标不超过 300 GB；源缓存、临时文件、权重和至少 20% 磁盘余量另列。

**停止条件：标签语义未解决或磁盘预算无法满足时，暂停大规模构建。**

## 7. S3：跨季节数据和独立切分

**目标：增加独立天气和区域覆盖，而不只是增加相关滑窗。**

### 任务

- 分级扩容：先争取冬春夏秋至少 4 个独立月份、约 40–60 个站点、至少 4 个地理组；前提是数据源与交集可用。
- 依据时间覆盖、元数据和预算选样，不按预测误差选择月份和站点。
- 开发月份之外，优先另取晚于开发期、从未查看的连续 4–8 周作为最终测试，并包含单独留出区域。该测试只支持实际覆盖季节的结论。
- 按绝对日期建立至少 3 个 expanding-window 开发回测；月份不连续时不拼接跨缺口滑窗。
- 保留至少 4 小时 embargo，并检查完整历史/目标支持区间及物理观测引用不跨切分。
- 地理留出报告训练站点距离、裁剪重叠与共享天气情况；区域不同不代表天气完全独立。
- 生成 QC 规则、日期、区域、站点统计；只在开发数据上诊断和调整可能误删真实积雪等情况的规则。
- 数据不足时缩小版本并降低结论范围，不能用旧暴露 test 冒充新独立测试。

### 交付与验收

- 新数据配置、manifest、数据卡、覆盖图及不可变 split manifest；旧版本不覆盖。
- 每折标准化仅从本折训练集拟合；最终测试不参与选站、调参、早停或统计拟合。
- 构建支持续跑和校验，相同来源与配置生成相同样本键。
- 时间、地理、质量和资源检查通过；无法支持的研究问题明确列出。

**审核点 G1：审核实际可用日期、站点与成本后，确定正式构建规模。**

## 8. S4：强无卫星基线与计算预算

**目标：为卫星提供有竞争力且成本透明的比较对象。**

### 实验任务

- 必选 Persistence、Smart Persistence、训练集 Climatology、PowerMLP，以及 CNN 框架内独立训练的 power_solar 对照。
- 增加一个树模型候选，使用功率、太阳与站点特征；不同时引入多个树模型库。
- TCN 先保留历史结果，仅在跨季节诊断提供理由时重跑或调参。
- 可预定义一个按时效选择或混合 Smart Persistence 与学习模型的候选；权重/选择只由开发验证决定。
- 新增模型各最多 4 组配置，单种子筛选；胜出配置再跑 42、123、2026，记录全部尝试。
- 共享数据、选择指标与回测折，报告参数量和预算；不同模型不必人为具有相同参数数量。

### 资源门禁

- 先完成至少 200 batch 采样和一个完整 epoch，测量 I/O、计算、RSS 与显存。
- 总预算按运行数、预计 epoch、实测 epoch 时间及评估开销计算，另列 20% 运行余量。
- GPU 不可用时仅先做正确性与成本估算，不默认启动预计耗时数天的 CPU 矩阵。
- 已批准资源范围内直接执行；新增付费资源或显著超出额度时，提供具体运行数和费用再确认。

### 验收

- 所有强基线具备跨窗口逐时效、日间、空间诊断和三种子结果。
- 胜出基线只在开发验证选择，正式比较目标集合一致。
- 多数窗口不如 Smart Persistence 时，检查语义和泛化；允许直接以 Smart Persistence 为胜出基线，不无上限调参。

**审核点 G2：确认强基线、核心矩阵及实测算力预算。**

## 9. S5：卫星核心对照

**目标：判断卫星是否增加有效信息。**

### 核心矩阵

- 三模式 power_solar、satellite_solar、full，每模式 3 seeds。报告真实字段白名单：当前 solar 模式也包含静态站点信息。
- 先做一个开发折，通过后扩展到 3 个回测折，最多 27 次核心训练。S4 协议一致的 power_solar 结果直接复用，不重复计数。
- 外部强 Power-only 和 Smart Persistence 均加入逐样本比较。
- 沿用当前 CNN 作为结构基准。缩小模型时创建新配置并重做相应对照，不能混合不同预算结果。
- 用参数上限约束资源，不把至少 5M 参数作为模型质量要求；取消当前下限需记录为协议变更。

### 诊断

- 独立训练无卫星模型是主要消融。full 置零与错配仅用于敏感性诊断，不能单独证明信息增益。
- 同一开发评估分区内选不同日期图像错配，排除历史重叠，尽量匹配太阳高度角，保存映射和 seed。
- 不跨 train/validation/test 借用图像；无法构造有效错配时明确跳过，不退回相近样本的假打乱。
- 用合成局部云运动检查模型对位置的敏感性，不把合成效果当作实际预测收益。

### 候选门与交付

- 主指标相对强基线改善至少 5%，至少 2/3 seeds、2/3 时间折改善：进入 S7；这只是工程门，不是统计显著性结论。
- 改善 0–5% 或不一致：做天气、站点、尺度和标签诊断，有具体假设才进入 S6。
- 多数折退化：检查对齐和输入有效性，检查无误后允许直接进入 S7/S8，以负结果交付。
- 交付 docs/SATELLITE_VALUE_DEVELOPMENT_REPORT.md、运行清单、预测、时效曲线和错配诊断，注明样本量、成本与限制。

## 10. S6：有条件进行空间结构改进

**目标：用有限实验解决一个明确问题。**

### 顺序与上限

1. 优先比较全局池化与保留粗空间网格，其余协议不变。
2. 若诊断支持，加入相对站点位置编码；几何 jitter 时同步更新位置表达。
3. 只有前两项显示价值时，考虑局部/大范围双尺度，区分视野变化与分辨率变化。
4. 残差预测作为另一候选，仅在强基线误差有可学习结构时采用。

最多选择上述 2 个候选做单种子筛选，只把一个候选扩展到三折三种子。单帧/四帧、通道消融按具体假设择一，不展开所有组合。每次只改变一个主要因素，报告参数量和耗时差异。

### 验收和停止

- 新模型同时与原 full 和强无卫星模型比较，增益不能仅归因于更多训练预算。
- 两个候选均无改善则结束架构升级，提交负结果，不转向更复杂模型继续无边界搜索。
- 胜出配置进入 S7，仍不查看最终测试。

**审核点 G3：仅在需要时审核具体假设与新增预算；范围内例行检查不重复询问。**

## 11. S7：稳健性与爬坡审计

**目标：确定改善可信度与预警价值。**

### S7.1 统计分析

- 同一目标上配对比较模型误差，以日期为块同时重采样当天所有站点，保留日内与站点间相关性。
- 至少 2,000 次 bootstrap，固定 seed；另用连续 3 日块分析相关性敏感性。
- 报告绝对 MAE 差值和相对 skill 的 95% 区间；基线误差接近零时不报不稳定百分比。
- 不把模型种子当作独立天气样本。单模型策略报告逐种子及平均损失；集成预测单独定义和评分。
- 各时间折分别报告；窗口重叠时按冻结规则去重，不能重复计数。
- 日期太少或区间宽时标记证据不足，增加 bootstrap 次数不能代替增加独立日期。
- 天气分组只在开发数据定义。用目标期观测划分的组标为事后诊断，不能直接作为实时模型路由特征。

### S7.2 爬坡事件

- 保留未来 30 分钟归一化功率变化 ±0.20 主阈值，上升下降分别评估；0.10/0.15/0.25 为预定义敏感性。
- 合并连续滑窗对同一过程的命中，冻结事件起止、合并间隔和方向规则，避免重复警报虚增事件数。
- 一对一匹配覆盖多预测争抢一个事件等用例，结果不能依赖输入排列。
- ±15 分钟容忍命中与严格提前预警分开。只有发布时间早于事件起点才计算正提前量，晚报不能算提前成功。
- 输出事件数、Precision/Recall/F1、每站日误报、漏报、提前量与事件期间 MAE。
- 日期块重采样后重新计算事件统计，不直接平均逐日 F1。
- 每方向每分区少于 100 个独立事件时仅描述性报告；达到 100 个也不自动保证充分，仍看区间和覆盖。
- 区分单站、站点宏平均和容量加权组合；区域聚合保留误差相关性，不假设误差独立相消。

### 交付与验收

- docs/ROBUSTNESS_REPORT.md、docs/RAMP_REPORT.md：分组样本量、区间、成功与失败案例。
- 稳健卫星增益需满足实用改善门、配对区间支持改善，并在多数 seeds/回测折方向一致；否则分类为有限增益、证据不足或无增益。
- 经济价值只做透明的误报/漏报成本情景；没有真实市场规则与价格，不宣称实际收益。

## 12. S8：最终测试与结论冻结

**目标：验证已确定方案，结束模型选择。**

### 冻结清单

- 数据、QC、切分、可用性假设、输入字段、标准化和训练截止时间。
- 模型配置、seed 或集成策略、训练预算、早停/固定 epoch 规则。
- 主指标、基线身份、事件规则、天气组、bootstrap、异常与缺失处理及后处理。
- checkpoint、代码版本、运行预算和预定义成败标准。

### 执行与验收

- 如用 train+validation 重训，先由开发回测确定固定 epoch 等策略，再拟合对应训练统计，不通过 test 早停。
- 显式最终评估入口执行一轮预登记模型和基线比较，保存原始预测与完整身份。
- 基础设施失败可按同一冻结身份重试。看过结果后发现影响结论的实现错误，披露问题，为后续调参建立新未见数据。
- 成功或负结果都完整发布，不能删除失败窗口重新报告。
- 同步 README、模型卡和数据卡，区分旧冬季开发数字与新独立结果。

**审核点 G4：审核具体冻结清单与预算。若批准计划已包含最终测试且范围未变，满足清单后执行，不重复请求授权。**
