# ADR-005：评估 V2、历史测试曝光与成果复用

- 状态：Accepted for S0；实现由 S1 及后续阶段完成
- 日期：2026-09-10
- 协议：c2w-eval-v2.0
- 取代范围：ADR-004 的未来测试角色和旧选择协议；保留其历史版本、完整时间支持区间和 embargo 原则

## 背景与证据

BASELINE_REPORT.md 已公开 paired-30d-v1 的 test/development 与 test/holdout。outputs/runs/naive-baselines-v1-9f3d90ef59fc 及 outputs/runs-pr5-repro 下同名运行均记录 test_unlocked=true。旧报告的“一次最终评估”需要理解为一次冻结配置的测试比较及另一次复现，不能表述为只发生过一次读取。

后续 Power-only/CNN/Optical Flow 产物的 test_unlocked=false 与此不冲突：它描述本运行未输出测试评分，而非整个项目从未看到测试结果。当前训练入口读取整张包含各分区的功率表后才选行，故“未评估”和“底层未读取”也不能混同。

另有选择指标差异：Power-only 和 CNN 配置列出 30/60/120 分钟，但训练实际使用六时效有效目标的平均误差进行早停和 best checkpoint 选择。既有结果保留，其身份不会因文档变更自动变成 V2。

## 决策

1. 当前 30 天数据及已曝光 test 降为历史开发资料，不删除、不重写旧数值，不声称发现了训练标签泄漏。
2. 采用 EVALUATION_PROTOCOL_V2.md：目标时刻太阳高度角>5°，30/60/120 分钟 MAE 等权平均为唯一主选择指标；全天结果并列报告。
3. 正式卫星增量以最强无卫星 B* 为主参照，并要求与独立匹配 power_solar 比较；不以弱 Persistence 的大百分比替代主比较。
4. S3 新建晚于开发期的未查看时间窗口和独立地理组，具体日期在可用性核查后冻结。开发区域验证不冒充最终区域测试。
5. 已有运行分为历史已完成、冒烟、完整性待核实、未完成与非实验缓存；“V1 可复用”不等于“可直接用于 V2 正式胜出”。
6. 不再设置至少 5M 参数的质量门；保留资源上限并要求公平报告配置与预算。正式训练前由 S1 改实现。
7. 实际执行身份、版本与预算在阶段门登记；用户本次 S0 指令不扩展为训练、下载或付费资源授权。

## 后果

旧 checkpoint 的新日间评分可以作为诊断，但不能补足当时缺失的 V2 checkpoint 选择。正式新数据/新协议学习实验需重训，基线代码与数据管道则继续复用。

任何尚未被历史产物证明的代码状态、依赖环境或恢复步骤明确标记未知。通过小样本完整性检查或权重有限性不等于重现了原训练；本次审计不进行新训练或模型推理。
