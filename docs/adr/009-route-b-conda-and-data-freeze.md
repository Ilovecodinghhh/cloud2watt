# ADR-009：执行路线 B，复用 Conda GPU 环境并冻结开发数据范围

日期：2026-10-02；状态：已接受，按阶段验收执行。
依据：用户明确要求“依据总方案的优先级开始逐个排查与执行。采取路线 B 计划”，
并要求“不用本项目安装的 pytorch，查找已有 conda 环境，数据放 D 盘”。
本决策更新 ADR-008 的路线顺序和 ADR-007 的扩容授权状态。

## 决策

1. 路线 B 已获授权。先完成 E00/E01/E02 和数据正确性前置门槛，再在新开发折进行强基线与卫星对照。
   不要求先跑满路线 A 的所有候选；也不跳过防泄漏、共同样本和训练预算控制。
2. 固定解释器为 C:/Users/admin/miniforge3/envs/raincalib-gpu/python.exe。
   实测 PyTorch 2.11.0+cu128，CUDA 可用，RTX 5070 Ti Laptop GPU。
   该 Conda 环境实际在 C 盘；D 盘保存数据、缓存、日志和模型。
   不使用项目 .venv 的 PyTorch，不改动现有 Conda 依赖。临时新建的运行环境已移除。
3. 冻结配置见 [route-b-freeze.json](../../configs/project-v2/route-b-freeze.json)。
   2021 年冬季 fit 加春夏秋开发窗口，三个滚动开发折；2022-01-01 至 2022-02-26
   为锁定最终时间窗口，第四区域为锁定地理组。窗口结束均为不含端点。
   每个样本的原始历史与全部目标支持必须在所处分区内；inner/outer 之间至少四小时隔离。
4. 站点必须在冻结版本的 2021 年 1 月五分钟文件中实际出现；只读取 ID 做候选筛选。
   早期仅根据元数据起止时间的候选作废，原因是其中可能只有半小时记录。
   修正预检得到 884 个五分钟 ID，再按冻结空间规则选出四区各十站。
   后续不得根据 outer 或最终测试误差替换站点。开发 QC 不足时记录失败并新增决策。
5. 先构建 r0、2021-01-01 至 2021-01-03 的工程样本，最多两天、一个区域。
   该样本只能验收数据与运行条件，不作卫星优越性证据。
6. 源缓存独立目录，最多 4 GiB；单响应最多 16 MiB；累计源传输最多 100 GiB。
   所有新增持久数据/缓存/模型先收紧为 16 GiB，磁盘至少保留总容量 20% 空闲；二者先到先停。
   下载预算跨重启保留，失败请求保守计费。缓存仅淘汰自有对象，旧缓存与历史数据不删除。
   当前缓存只支持一个构建进程，正式批量构建前补断点恢复和调度验收。
7. 正式神经训练最多 72 GPU 小时，其他运行数和 epoch 上限沿用总方案。
   当前采用 FP32；真实数据的 200 batch 吞吐、完整 pilot epoch 和确定性优化器续跑已验收。
   AMP 训练、随机加载/增强的跨进程恢复仍属 E02 待办，详见执行记录。
8. 独立测试标签继续锁定，当前不下载或构建 2022 测试标签，不训练第四区域的历史标签。
   预检显示最终窗口缺 192 个卫星坐标时隙；保留原窗口并报告可用率，不能据此挑换日期。
