# Cloud2Watt 项目设计与实施计划

版本：0.1  
状态：设计草案  
最后更新：2026-09-04

## 1. 项目定位

Cloud2Watt 是一个面向能源气象、遥感与机器学习岗位的作品集项目。项目使用过去一小时的地球同步气象卫星云图、近期光伏出力、太阳位置与静态站点信息，预测未来 0–4 小时的光伏功率，并对短时间大幅升降的光伏爬坡事件进行预警。

项目不以堆叠大模型为目标，而以以下能力为核心：

- 构建真实、多源、时空对齐的数据管道；
- 建立不会发生未来信息泄漏的评估体系；
- 证明卫星云图相对于纯时序基线的增量价值；
- 将预测精度转换为可解释的爬坡预警能力；
- 交付可复现训练、回测、推理和可视化演示。

### 1.1 核心研究问题

项目依次回答四个问题：

1. 仅使用近期光伏功率，未来 15–240 分钟可以预测到什么程度？
2. 加入太阳位置和晴空先验后，是否能稳定超过朴素持续性预测？
3. 加入卫星云图后，在哪些预测时效和天气条件下产生显著增益？
4. 功率误差的改善能否转化为更准确、更早的爬坡事件预警？

### 1.2 MVP 范围

第一版只做以下范围：

- 区域：英国；
- 目标：站点级归一化光伏功率；
- 输入历史：过去 60 分钟；
- 采样间隔：15 分钟；
- 预测时效：15、30、60、120、180、240 分钟；
- 卫星空间窗口：以站点为中心的 128 × 128 像素裁剪；
- 输出：确定性多时效功率预测与 30 分钟爬坡事件；
- 模型：四个可解释基线和两个中小型深度模型；
- 交付：数据清单、训练脚本、回测报告、案例动画和本地推理 API。

第一版明确不做：全球范围、实时生产部署、从零训练天气大模型、完整全盘卫星数据下载、扩散模型和储能调度。概率预测在确定性模型跑通后再进入第二版。

## 2. 成功标准

### 2.1 最低可交付标准

- 一条命令可以生成小型、无许可风险的合成样例并完成冒烟训练；
- 数据清单能追溯每个原始文件的来源、时间范围、许可证和校验和；
- 时间切分、标准化和特征生成均有防泄漏测试；
- Persistence、Smart Persistence、历史功率模型和卫星融合模型均可复现；
- 每个预测时效都报告 MAE、RMSE、nMAE 和相对 Persistence 的 skill score；
- 爬坡事件报告方向感知的 Precision、Recall、F1 和提前量；
- 固定测试集只在模型选择结束后用于一次正式评估；
- GitHub CI 通过，README 能让新用户在 15 分钟内运行小样例。

### 2.2 目标标准

- 卫星融合模型在 30–120 分钟的测试集 nMAE 上稳定优于 Smart Persistence；
- 至少在一个关键时效上，相对 Smart Persistence 的 MAE skill score 达到 5% 以上；
- 卫星模型对 30 分钟、容量归一化变化绝对值不小于 0.20 的爬坡事件，F1 高于无卫星模型；
- 结果包含 bootstrap 置信区间，避免把随机波动解释成模型改进；
- 在 12 GB 显存上可训练，单次标准实验尽量控制在 12 小时以内。

这些是工程目标而非预先承诺的实验结论。如果卫星输入没有改善，应如实报告负结果并分析数据质量、空间尺度和标签噪声。

## 3. 数据方案

### 3.1 主路线

| 模态 | 首选来源 | 用途 | MVP 获取策略 |
|---|---|---|---|
| 光伏功率 | Open Climate Fix `uk_pv` | 站点级标签与历史功率 | 先申请访问，仅下载所选月份和站点 |
| 卫星云图 | OCF 公共 EUMETSAT SEVIRI RSS Zarr | 云系位置、纹理与移动 | 远程读取后只缓存英国和站点周边裁剪 |
| 太阳位置 | `pvlib` 计算 | 晴空先验和昼夜过滤 | 根据近似经纬度和 UTC 时间本地计算 |
| 站点元数据 | `uk_pv` metadata | 容量、位置、倾角与朝向 | 只保存允许再分发的派生字段和清单 |
| 可选 NWP | DWD ICON-EU | 120–240 分钟补充信息 | 第二版再加入，避免 MVP 失焦 |

选择英国路线的原因：OCF 已公开同类项目的数据结构和模型生态；`uk_pv` 提供站点容量、约 1 km 精度的位置和 5 分钟发电数据；PVNet 给出了公开卫星 Zarr 路径和多模态建模参考。`uk_pv` 是 gated 数据，使用前需要接受条件并配置 Hugging Face token。

参考资料：

- [OCF UK PV 数据集](https://huggingface.co/datasets/openclimatefix/uk_pv)
- [OCF PVNet](https://github.com/openclimatefix/PVNet)
- [OCF Data Sampler](https://github.com/openclimatefix/ocf-data-sampler)
- [EUMETSAT 数据注册与许可](https://user.eumetsat.int/resources/user-guides/data-registration-and-licensing)

### 3.2 数据访问硬门槛

在编写完整管道前，先完成一个不超过两天的 Data Access Spike：

1. 获得 `uk_pv` 访问权限并读取 metadata；
2. 读取一个月的 5 分钟功率数据；
3. 从卫星 Zarr 读取一个时刻、一个英国空间子集和至少三个通道；
4. 验证卫星时间、功率区间结束时间和站点位置可以正确对齐；
5. 生成 20 个站点、7 天数据的本地 mini dataset；
6. 记录下载字节数、解压峰值内存、读取速度和最终磁盘占用。

硬门槛通过条件：

- 两种数据至少存在连续 30 天交集；
- 目标时刻前的卫星帧能够稳定获取；
- 单个训练样本可在 100 ms 量级从本地缓存读取；
- 小样本端到端处理没有时区或投影错误；
- 扩展到一年、100–300 个站点后的预计处理数据不超过约 300 GB。

PVNet 文档指出公共卫星 Zarr 当前使用 `blosc2`，与其 TensorStore 后端不兼容。因此本项目首阶段不直接依赖 PVNet 数据加载栈，而是验证 `xarray`/`zarr`/兼容 codec 能否读取，并将所需裁剪转换为本地、版本化的 Zarr。不得在未验证按块读取前下载完整卫星档案。

### 3.3 备用路线与止损

按以下顺序切换，任何切换都记录为 ADR：

1. OCF 公共卫星 Zarr可读：采用主路线；
2. Zarr codec 不兼容但 EUMETSAT 可下载：注册 EUMETSAT，下载有限日期的历史 SEVIRI 数据并本地转换；
3. 站点级功率无法获得：改用英国 GSP 区域级 PV Live 标签，空间裁剪中心改为 GSP 区域质心；
4. 只有短时间交集：缩短预测研究期，但保留跨季节月份，并降低结论外推范围；
5. 两周内仍无法形成 30 天配对数据：暂停模型开发，优先解决数据源，不用合成数据冒充正式实验。

### 3.4 数据模型

统一样本键：

```text
(site_id, issue_time_utc)
```

每个样本包含：

```text
satellite:      [history_steps, channels, height, width]
power_history:  [history_steps]
solar_features: [history_steps + forecast_steps, feature_count]
site_features:  [capacity, tilt, orientation, latitude, longitude]
target_power:   [forecast_steps]
target_mask:    [forecast_steps]
metadata:       site_id, issue_time_utc, source versions, quality flags
```

功率统一转换为平均功率，再除以站点 `kWp` 得到归一化功率。保留原始值，不静默裁剪；超过合理物理范围的记录通过质量标志排除。`uk_pv` 数据卡对 5 分钟数据同时出现“瞬时读数”和按区间能量换算的描述，正式转换前必须通过样本分布、字段 schema 和上游说明解决该语义歧义；30 分钟数据则明确是以时间戳结尾的区间累计能量。

### 3.5 质量控制

- 所有时间进入管道后立即转换为带时区的 UTC；
- 应用数据源发布的 `bad_data.csv`；
- 排除负发电量、夜间非零发电、白天长时间卡零和异常尖峰；
- 只在训练集拟合缺失值策略和标准化统计量；
- 输入窗口中任一关键卫星帧缺失时，设置 mask 或丢弃样本，不前向填充未来信息；
- 记录每项过滤规则删除的样本数量；
- 对卫星图做海岸线或已知城市位置的人工投影抽查；
- 数据切分前先按时间去重，再按样本键验证唯一性。

## 4. 数据切分与防泄漏

### 4.1 主评估：已知站点的时间泛化

先获取实际时间交集，再确定绝对日期。推荐比例：

- 最早 70% 连续时间：训练集；
- 接下来 15%：验证集；
- 最后 15%：测试集；
- 切分边界之间设置至少 4 小时 embargo，防止滑窗共享输入或标签。

测试集在特征、阈值和模型选择冻结后才运行。验证阶段使用 expanding-window backtest，至少覆盖三个不同季节的窗口。

### 4.2 次评估：未见站点的空间泛化

从站点中固定留出约 20%，同时让训练和测试站点在容量、纬度和数据完整率上尽量分层。该实验回答模型能否迁移到新站点，不与主时间测试集混为一个数字。

### 4.3 泄漏检查清单

- 晴空指数、标准化、异常阈值只使用训练数据拟合；
- 任何 NWP 输入必须是 issue time 当时可获得的预报版本；
- 卫星输入时间不得晚于 issue time；
- 目标窗口不得与输入窗口重叠；
- 同一物理观测不能因重采样同时出现在切分两侧；
- 选择最好 checkpoint 只能使用验证集；
- 测试结果生成后不再调整模型。

## 5. 预测任务与指标

### 5.1 功率预测

模型一次直接输出六个时效，默认优化加权 MAE：

```text
L_power = Σ_h w_h × MAE(y_h, ŷ_h)
```

第一版时效等权；后续可提高 30–120 分钟权重。输出通过合适的激活或后处理限制在合理范围，但同时报告裁剪前异常率。

核心指标：

- MAE、RMSE；
- nMAE：MAE 除以装机容量；
- MAE skill score：`1 - MAE_model / MAE_reference`；
- 分时效、月份、太阳高度角和天气波动等级的指标；
- 以日期为 block 的 bootstrap 95% 置信区间。

### 5.2 爬坡事件

默认事件定义：未来 30 分钟内，归一化功率变化绝对值不小于 0.20；上升与下降分别评估。阈值必须在测试前冻结，并额外报告 0.10、0.15、0.25 的敏感性分析。

事件指标：

- Precision、Recall、F1；
- 上升和下降事件的混淆矩阵；
- 在 ±15 分钟容忍窗口下的事件命中率；
- 正确预警的中位提前量；
- 事件期间的功率 MAE。

## 6. 模型路线

### 6.1 基线阶段

按顺序实现，未超过前一个基线时不升级复杂模型：

1. Persistence：所有时效等于最后观测功率；
2. Smart Persistence：保持当前晴空指数，结合未来太阳位置恢复功率；
3. Seasonal/Climatology：同站点、相近日时和月份的训练集统计量；
4. Power-only MLP/TCN：近期功率、太阳位置和站点元数据，不使用卫星。

### 6.2 卫星模型阶段

首个卫星模型采用轻量 late fusion：

```text
卫星序列 ── CNN encoder + temporal pooling ─┐
历史功率 ── TCN/GRU ────────────────────────┼─ Fusion MLP ─ 多时效功率
太阳特征 ── MLP ───────────────────────────┤
站点信息 ── MLP ───────────────────────────┘
```

该模型先证明卫星信息是否有增量价值，再比较：

- ConvLSTM：显式学习云系时序演变；
- 3D CNN：作为更简单的时空卷积比较；
- Optical Flow 特征：把估计云移动向量作为可解释输入；
- U-Net 云图外推：仅在直接功率预测已稳定后作为辅助任务。

模型约束：默认参数量不超过 30M；混合精度训练；128 × 128 输入；显存不足时优先降低 batch size、通道数和 encoder 宽度，不先降低时间覆盖。

### 6.3 消融实验

最终报告至少包含：

- 历史功率；
- 历史功率 + 太阳特征；
- 卫星 + 太阳特征，不含历史功率；
- 全部输入；
- 单帧卫星与多帧卫星；
- 不同空间裁剪大小；
- 可见光/红外通道组合；
- 有无站点静态信息。

每次只改变一个主要因素，使用相同切分、seed、训练预算和早停规则。

### 6.4 第二版扩展

只有 MVP 达标后再考虑：

- P10/P50/P90 分位数预测；
- conformal calibration 和区间覆盖率；
- 加入 ICON-EU NWP 改善 2–4 小时时效；
- 图像外推与功率预测多任务学习；
- 跨区域或跨国家迁移。

## 7. 软件架构

目标目录：

```text
cloud2watt/
├── configs/
│   ├── data/
│   ├── experiment/
│   ├── model/
│   └── base.yaml
├── data/
│   └── README.md
├── docs/
│   ├── PROJECT_PLAN.md
│   ├── DATA_CARD.md
│   ├── MODEL_CARD.md
│   └── adr/
├── notebooks/
│   └── exploration/          # 只做探索，不承载核心逻辑
├── scripts/
│   ├── download_pv.py
│   ├── inspect_satellite.py
│   ├── build_dataset.py
│   ├── train.py
│   └── evaluate.py
├── src/cloud2watt/
│   ├── data/
│   ├── features/
│   ├── models/
│   ├── evaluation/
│   ├── visualization/
│   └── api/
├── tests/
│   ├── unit/
│   ├── integration/
│   └── fixtures/
└── .github/workflows/
```

设计原则：

- `scripts/` 只解析参数并调用 `src/`，业务逻辑必须可测试；
- 配置文件记录数据版本、切分、模型和随机种子；
- 原始数据只读，派生数据写入新目录；
- 每次实验输出配置快照、Git commit、依赖版本、指标和模型摘要；
- 密钥只从环境变量读取，`.env` 永不提交；
- 小型合成 fixture 进入 Git，真实数据和权重不进入 Git。

## 8. 测试与持续集成

### 8.1 单元测试

- 时间区间语义和 UTC 转换；
- 功率单位与归一化；
- 滑窗边界和 embargo；
- 缺失帧 mask；
- 爬坡标签；
- 指标与 skill score；
- 张量形状和模型前向传播。

### 8.2 集成测试

- 合成数据从原始格式到训练 batch；
- 10 个 batch 的 CPU 冒烟训练；
- checkpoint 保存、加载与确定性推理；
- 回测结果 schema；
- API 输入校验。

### 8.3 CI 分层

- 每个 PR：Ruff、单元测试、合成数据集成测试；
- 定期或手动：GPU 训练冒烟测试；
- 不在公共 CI 下载 gated 或 TB 级数据；
- 所有外部数据测试通过 mock、小 fixture 或显式 opt-in 运行。

## 9. 实验管理与可复现性

每次实验必须记录：

```text
run_id
git_commit
config_hash
data_manifest_hash
train/validation ranges
site split hash
random seeds
hardware and package versions
metrics by horizon
checkpoint path
```

首阶段使用本地 JSON/CSV 和结构化输出目录即可，不急于引入 MLflow。实验数量增多后再评估 MLflow 或 Weights & Biases。重要结果必须能由命令行配置重现，不能只存在于 notebook。

## 13. 主要风险

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 卫星数据规模过大 | 磁盘和网络成为瓶颈 | 按块远程读取、只缓存空间裁剪、先估算年度体积 |
| Zarr codec 不兼容 | 无法读取 OCF 公共数据 | 两天 spike；直接用兼容 codec；必要时转 EUMETSAT 下载 |
| 数据许可限制 | 不能公开原始数据 | 仓库只放代码、清单与合成 fixture；明确归属 |
| 站点位置被模糊 | 卫星裁剪存在空间误差 | 使用足够大的裁剪，并做空间扰动敏感性分析 |
| PV 标签噪声和缺测 | 模型学习错误模式 | 应用官方 bad-data 清单，报告 QC 删除量 |
| 时间泄漏 | 指标虚高 | UTC、embargo、train-only normalization 和自动测试 |
| 稀有爬坡事件类别不平衡 | F1 不稳定 | 方向分层、PR 曲线、block bootstrap、阈值敏感性 |
| 12 GB 显存限制 | 大模型无法训练 | 128 像素裁剪、AMP、小 batch、梯度累积、30M 参数上限 |
| 项目范围膨胀 | 长期无法交付 | 先完成确定性 MVP；NWP、概率预测和扩散模型后置 |

## 14. 决策门与 Definition of Done

### 数据门

没有 30 天以上的真实配对数据，不进入正式模型开发。

### 基线门

Persistence 和 Smart Persistence 没有可靠复现，不训练卫星深度模型。

### 卫星价值门

卫星融合模型必须在固定验证方案下与相同预算的 power-only 模型比较；如果没有增益，先做数据、空间窗口和天气分组诊断，不直接换更大模型。

### MVP 完成定义

当以下条件全部满足时发布 `v0.1.0`：

- 数据版本与切分可追溯；
- 至少四个基线和一个卫星模型完成同协议评估；
- 测试集结果、置信区间和失败案例已经写入报告；
- 爬坡事件评估完成；
- CI、安装、冒烟训练与推理演示通过；
- README、数据卡、模型卡和限制说明完整；
- 仓库不包含密钥、受限原始数据或大模型文件。
